THE LOOP

          
One loop. Not a platform.

        

        
Each step leaves a file. If it is not on disk, it does not exist. That is the whole trick.

      

      

        
01 / PROFILE
Ask, don’t assume
Who, goals, one repeated task, acceptance, privacy. 5–8 questions, one at a time.

        
02 / WORKSPACE
Give it a desk
PROFILE.md, RULES.md, memory/, docs/, evals/. Local, readable, git-friendly.

        
03 / FIRST RUN
Do one real task
An artifact, an evidence file, a handoff. No “here’s a plan” theatre.

        
04 / CORRECTION
Make it stick
“That’s wrong” becomes a numbered rule + an eval case, not a one-off apology.

        
05 / EFFORT
Choose the budget
low / medium / high. High means more checks, not more words.

      

    

  


  

    

      

        

          
BEFORE / AFTER

          
The second run is the product.

        

        
A generic agent answers. A growing assistant cites your files, follows your rules, and shows what changed.

      

      

        

          
Generic agent

          
“Here’s a polished answer.”

          
    
            
  • Starts from zero every session.
    • 
            
  • Invents a plausible number.
    • 
            
  • Forgets the correction by tomorrow.
    • 
            
  • No evidence, no rollback.
    • 
          

          
chat history ≠ memory

        

        

          
Growing assistant

          
“Here’s the same task, with your rule.”

          
    
            
  • Reads PROFILE.md and RULES.md first.
    • 
            
  • Cites docs/resume.md#experience.
    • 
            
  • Rule R-002 prevents “负责” when it was “协助”.
    • 
            
  • Re-runs E-002 and shows the diff.
    • 
          

          
the correction is in the repo, not in the chat

        

      

    

  


  

    

      

        

          
INSIDE

          
A workspace you can read.

          

assistant/
├─ PROFILE.md      # who, goals, privacy
├─ RULES.md        # one rule per correction
├─ WORKFLOW.md     # inputs, steps, acceptance
├─ memory/         # dated notes, open loops
├─ docs/           # read-only source material
├─ evals/          # good/bad cases
├─ output/         # report + evidence + handoff
├─ skills/         # distilled standalone skills
└─ private/        # gitignored
          

        

        

          
No database server. Markdown + folders. You can read it, edit it, diff it, and put it in Git.

          
No model lock-in. The skill runs in any Agent that can read/write files and run Python. WorkBuddy, Claude Code, Codex, Pi.

          
No multi-agent ceremony. One assistant first. Roles are a later option, not the starting point.

INSTALL

          
Start with one workflow.

        

        
Pick the task you repeat every week. The skill will help you make it verifiable before it makes it fancy.

      

      

        
terminal

        
# 1. install
git clone https://github.com/zhoujinq/growing-assistant-skill.git
cp -r growing-assistant-skill/skills/growing-assistant ~/.workbuddy/skills/growing-assistant

# 2. scaffold a workspace
cd ~/.workbuddy/skills/growing-assistant
python scripts/init_assistant.py --root ./assistant --name "My Assistant"
python scripts/lint_assistant.py --root ./assistant

# 3. ask your Agent
“Build my growing assistant. Start with the first workflow: <your repeated task>.”

      

    

  


  

    

      

        

          
DESIGN NOTES

          
Small on purpose.

        

        
Three ideas from the GSE labs, stripped of course-specific parts.

      

      

        
LAB 1 / STATE
Save the correction
A successful flow and a correction must become a readable file. Chat is not memory. Git is.

        
LAB 2 / EFFORT
Pay for checks
High effort is solve → check → revise, not a longer answer. Keep the best version in the workspace.

        
LAB 3 / TASTE
Build the benchmark
Without good/bad cases, “grow” is just a promise. Each correction adds one case you can re-run.
