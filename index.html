循环

          
一个循环，不是平台。

        

        
每一步都留下一个文件。没落到磁盘上，就等于不存在。整套东西就靠这个。

      

      

        
01 / 档案
先问，不要猜
你是谁、要什么、哪件事每周重复、做完什么样、哪些不能看。5–8 个问题，一次一个。

        
02 / 工作区
给它一张桌子
PROFILE.md、RULES.md、memory/、docs/、evals/。本地、可读、能进 Git。

        
03 / 首跑
做一件真事
一个产物、一份证据、一段交接。不要“我给你一个计划”的表演。

        
04 / 纠正
让它记住
“这不对”要变成一条编号规则 + 一个评测案例，而不是一句一次性的道歉。

        
05 / 努力档
选预算
low / medium / high。高档等于多检查，不是多写字。

      

    

  


  

    

      

        

          
前后对比

          
第二次运行，才是产品。

        

        
普通 Agent 给答案。会长大的助手会引用你的文件、遵守你的规则，并告诉你哪里变了。

      

      

        

          
普通 Agent

          
“这是一份漂亮的回答。”

          
    
            
  • 每次会话都从零开始。
    • 
            
  • 编一个看起来合理的数字。
    • 
            
  • 明天就忘了你纠正过什么。
    • 
            
  • 没有证据，也没法回滚。
    • 
          

          
聊天记录 ≠ 记忆

        

        

          
会长大的助手

          
“同一个任务，加上你的规则。”

          
    
            
  • 先读 PROFILE.md 和 RULES.md。
    • 
            
  • 引用 docs/resume.md#experience。
    • 
            
  • 用 R-002 拦住“负责”，因为原文只是“协助”。
    • 
            
  • 重跑 E-002，并把 diff 给你看。
    • 
          

          
纠正在仓库里，不在聊天里

        

      

    

  


  

    

      

        

          
内部结构

          
一个你能读懂的工作区。

          

assistant/
├─ PROFILE.md      # 你是谁、目标、隐私
├─ RULES.md        # 一次纠正一条规则
├─ WORKFLOW.md     # 输入、步骤、验收
├─ memory/         # 日期笔记、未决事项
├─ docs/           # 只读源材料
├─ evals/          # 好/坏案例
├─ output/         # 报告 + 证据 + 交接
├─ skills/         # 蒸馏出的独立 skill
└─ private/        # 不进 Git
          

        

        

          
没有数据库服务。Markdown + 文件夹。你能读、能改、能 diff、能进 Git。

          
不锁模型。只要能读写文件、能跑 Python 的 Agent 都能用：WorkBuddy、Claude Code、Codex、Pi。

          
不搞多 Agent 仪式。先做一个助手。角色是后面的选项，不是起点。

          

            
0个外部 Python 包

            
3道门：档案 / 首跑 / 成长

            
2个示例工作流

            
1条命令搭好骨架

          

        

      

    

  


  

    

      

        

          
安装

          
从一条工作流开始。

        

        
选你每周都在重复的那件事。这个 skill 会先帮你把它变得可验收，再谈漂亮。

      

      

        
终端

        
# 1. 安装
git clone https://github.com/zhoujinq/growing-assistant-skill.git
cp -r growing-assistant-skill/skills/growing-assistant ~/.workbuddy/skills/growing-assistant

# 2. 搭工作区
cd ~/.workbuddy/skills/growing-assistant
python scripts/init_assistant.py --root ./assistant --name "我的助手"
python scripts/lint_assistant.py --root ./assistant

# 3. 对你的 Agent 说
“帮我搭一个会长大的助手。从第一条工作流开始：<你每周重复的那件事>。”

      

    

  


  

    

      

        

          
设计注记

          
故意做小。

        

        
来自 GSE 实验的三个想法，去掉了课程特定的部分。

      

      

        
实验 1 / 状态
把纠正存下来
一次成功的流程、一次纠正，都要变成可读文件。聊天不是记忆，Git 才是。

        
实验 2 / 努力
为检查付费
高 effort 是“求解 → 检查 → 修改”，不是把答案写长。把当前最好版本留在工作区。

        
实验 3 / 品味
建评测集
没有好/坏案例，“成长”只是一句承诺。每次纠正加一个能重跑的案例。
