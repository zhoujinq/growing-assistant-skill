# 04 · Grow：纠正 → 规则 → 评测

## 先分类

| 类型 | 例子 | 改哪里 |
|---|---|---|
| 事实错 | 数字错、引用错、人名错 | 改源文件或 `evidence.md` |
| 规格错 | 输出格式不对、步骤漏了 | 改 `WORKFLOW.md` |
| 偏好 | “别用这个词”“先给结论” | 写 `RULES.md` |

分类错了，规则会越写越歪。

## 规则格式

```markdown
## R-00X <短标题>
- 触发：什么情况下生效
- 动作：必须做什么 / 不做什么
- 原因：为什么（一句话）
- 例子：正例 / 反例
```

规则要能执行。不要写“更专业一点”；写“先给结论，再给三条依据，不超过 300 字”。

## 评测格式

```markdown
# E-00X <案例名>

## Input
固定输入（文件/问题/数据）。

## Expected
可判定的期望（事实/格式/边界）。

## Bad output
一个真实反例，说明哪里错。

## Judge
谁来判、怎么判（人/规则/脚本）。
```

## 第二轮

改完规则后，用同一输入重跑：

- 规则是否被引用？
- 反例是否变红？
- 输出是否真的更好，而不是更长？

没有变好，说明规则写错了，不是模型不行。

## 成长日志

在 `memory/YYYY-MM-DD.md` 记一行：

```text
R-003 added: 先给结论，再给依据。E-003 added. Re-run: pass.
```

这就是“会成长”的最小证据。
