# 05 · Export：把稳定工作流蒸馏成独立 Skill

## 什么时候导出

满足三条再导出：

1. 同一工作流跑过至少 3 次。
2. 规则和评测稳定，最近一次没有新增规则。
3. 换一个新会话，只看文件也能跑通。

不满足就继续用 `WORKFLOW.md`，不要急着做 Skill。

## 独立 Skill 的结构

```text
skills/<name>/
├─ SKILL.md          # 路由 + 护栏 + 流程
├─ references/       # 按需加载的规范
├─ templates/        # 输入/输出模板
├─ scripts/          # 可执行检查（可选）
└─ examples/         # 一个最小正例 + 一个反例
```

`SKILL.md` 只做三件事：什么时候用、必须守什么、按什么顺序做。具体规范放 `references/`，不要全塞进入口。

## 导出检查

- [ ] 触发词明确，不会和已有 Skill 抢。
- [ ] 输入/输出契约写死。
- [ ] 至少一个正例、一个反例。
- [ ] 有一个能失败的检查（脚本或清单）。
- [ ] 不依赖作者本机路径/私有数据。
- [ ] 有一个“停止条件”，防止硬做。

## 案例页

静态页只展示四块：

1. 装 Skill 的命令。
2. 第一次任务（输入 → 产物）。
3. 一次纠正（规则 + 评测）。
4. 第二次任务（before/after 证据）。

不要放“功能列表 20 条”。别人只想知道：**装完能不能跑，跑了会不会变好。**
